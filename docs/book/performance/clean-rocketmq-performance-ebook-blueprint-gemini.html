02 · 六篇十八章完整目录与逐章大纲

第一篇：性能测试方法论、基线环境与架构解构 15% · 第 1~3 章
点击折叠/展开
  • 1.1 为什么 80% 的压测数据不可信？ — 以 CommitLogManagerBenchmark（多线程耗时累加）与 InsertBenchmark（分子硬编码）做第一手失真案例复盘。
  • 1.2 核心度量指标体系 — TPS/MB/s、分位延迟（P50~P99.9/Max）、协调遗漏（Coordinated Omission）与 Open-loop 定速、HdrHistogram 原理。
  • 1.3 分层剥离压测模型（L1~L6 金字塔） — 用短板转移模型阐明六层压测如何精准定界。
  • 2.1 五大模块与核心数据流全景 — common / rpc / registry / store / broker 职责边界与线程模型。
  • 2.2 写入链路上的 5 个关键性能关口 — gRPC/Protobuf → Broker EnqueueService → Store EnqueueLock → CommitLogManager 分片 → DefaultFlushHandler。
  • 2.3 消费、派发与高级特性链路 — DispatchManager、DequeueService（Pop/Ack/Renew/Revive/OrderLock）、TimerWheel、TransactionBootstrap。
  • 2.4 存算一体（Embed）与存算分离（Remote）的性能边界 — StoreBootstrap 双模式切换与演进边界。
  • 3.1 硬件拓扑与施压机隔离规范 — 物理隔离、NVMe 队列深度、万兆网卡、关闭 CPU 节能与 NUMA 策略。
  • 3.2 Linux 内核参数基线调优 — PageCache 脏页比例（vm.dirty_*）、vm.max_map_count、FD 与 TCP 缓冲。
  • 3.3 JVM 参数基线与预热纪律 — JDK 21+（--enable-preview）G1 vs ZGC、MaxDirectMemorySize、JIT Warmup 与 PageCache 清理规范。
第二篇：底层微基准与存储引擎压测实战（L1 ~ L2） 25% · 第 4~7 章 ★核心
点击折叠/展开
  • 4.1 搭建 JMH 工程体系（test/performance） — 消除死代码、防止常量折叠，结合 -prof gc 与 -prof async。
  • 4.2 消息编解码与位点计算基准 — MessageEncoder/Decoder（128B~64KB）与 OffsetCodec 分片位运算开销。
  • 4.3 并发锁原语竞争测试 — CommitLogReentrantLock、EnqueueLock、DequeueLock 1~32 线程退化曲线。
  • 4.4 内存映射与堆外缓冲池基准 — DefaultMappedFileQueue vs TransientPool 与 AllocateMappedFileService 预分配。
  • 5.1 基准代码重构实战 — 修复 CommitLogManagerBenchmark 与 InsertBenchmark 的墙钟计时、刷盘对齐与 future.get()。
  • 5.2 分片数量扩展性实验（验证 5x+ 吞吐） — shardingNumber = 1/2/4/8/核数 × 并发线程梯度，输出加速比曲线与 Lock 火焰图对比。
  • 5.3 单盘 vs 多盘（enableMultiDir）与绑核（bindShardingWithCpu） — 区分锁上限与单盘带宽上限，验证绑核对 P99.9 毛刺收益。
  • 6.1 刷盘机制深度对比（DefaultFlushHandler） — ASYNC vs SYNC（GroupFlusher 组提交）帕累托曲线与 enableWriteCache 敏感性。
  • 6.2 enablePreAssignOffset 开关收益量化 — 热点单队列 vs 均衡多队列下的吞吐增益与可见延迟代价。
  • 7.1 DispatchManager 异步派发追赶压测 — 核验多分片高写入下默认 dispatchThreads = 5 是否形成 Dispatch Lag。
  • 7.2 ConsumeQueue 对比：File Mmap vs RocksDB — 10 Topic 与 1,000+ Topic 随机小 IO 写放大、读延迟与恢复速度。
  • 7.3 DequeueService 与 TimerWheel 组件压测 — Pop + Checkpoint + InflightCounter 吞吐与时间轮惊群/离散到期精度。
第三篇：网络通信与计算接入层压测（L3） 12% · 第 8~9 章
点击折叠/展开
  • 8.1 rpc 模块纯网络基准 — NettyClient/Server 连接复用、128B~1MB 包长、Sync/Async/Oneway QPS 与 RTT。
  • 8.2 registry 注册中心高并发压测 — 大规模 Topic 路由拉取、高频 Store 心跳与变更锁争抢。
  • 9.1 构建无磁盘 I/O 的 Mock MQFacade Broker — 纯测 GrpcServer(:8081) + Protobuf + producerThreadNum 调度上限。
  • 9.2 瓶颈转移分析：当存储快了 5 倍之后 — 对比 L2 与 L3 曲线，评估 gRPC 与回调线程池是否成新短板。
  • 9.3 EmbedStore vs RemoteStore 跨进程 RPC 损耗评测 — 量化存算分离网络 RTT 与序列化 CPU 代价。
第四篇：端到端全场景压测与横向对标（L4） 20% · 第 10~12 章 ★重点
点击折叠/展开
  • 10.1 重构 test/e2e/benchmark 套件 — 复用 Producer、扩展异步/批量/Pop 消费与定速施压，修复 Report / BenchmarkSuit 统计缺陷。
  • 10.2 接入 OpenMessaging Benchmark (OMB) — 复用 RocketMQ 5.x gRPC Driver 与标准 Workload，实现可复现压测与自动出图。
  • 11.1 基础 Pub/Sub 场景矩阵 — Sync/Async/Batch × 消息体大小（128B/1KB/4KB/64KB）× Topic/Queue 分布。
  • 11.2 热读 vs 冷读混合压测 — 实时追尾热读 vs 积压 50GB+ 回源随机冷读对前台写入 P99 的拖累。
  • 11.3 Pop 消费全生命周期开销 — Pop → Ack 基准 vs 叠加 Renew 续期、超时 Revive 重试的写放大。
  • 11.4 三大高级特性性能衰减曲线 — 顺序消息（FIFO 锁）、延时消息（Timer 到期误差 P99）、事务消息（TCC 写放大与回查压力）。
  • 12.1 公平对标准则（Apples-to-Apples） — 对齐硬件、JVM、FlushType、SDK 与压测负载。
  • 12.2 多维度对比实验与数据解读 — 单分片默认模式对比 + 多分片与异步位点模式对比（量化核心领先幅度与边界）。
第五篇：集群高可用与长稳混沌压测（L5 ~ L6） 14% · 第 13~15 章
点击折叠/展开

  • 13.2 流控与分片复制瓶颈分析 — 评测 maxHaTransferBytesPerSecond、maxHaTransferSize 与 maxSlaveGap 影响。
  • 14.1 集群水平扩展线性度实验 — 1 → 2 → 4 → 8 节点扩容下的聚合吞吐线性度与路由均衡性。
  • 14.2 存算分离独立扩缩容验证 — 扩容无状态 Broker 破协议瓶颈 vs 扩容 Store 破磁盘瓶颈。
  • 15.1 24h~72h 恒定压力长稳测试（test/stability） — 堆内存、DirectMemory、Mmap 句柄与 GC 漂移监控。
  • 15.2 磁盘水位、过期清理（Retention）与积压追赶 — 周期性文件清理毛刺与海量积压追赶 I/O 争抢治理。
  • 15.3 极限过载背压与故障恢复 SLA — 超阈值限流表现；kill -9 与 tc 网络故障后的 Recovery 耗时与零丢校验。
